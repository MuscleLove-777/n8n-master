n8n Cloud 料金プラン 2026完全ガイド

この記事でわかること

  • n8n Cloud 料金プラン 2026のStarter、Pro、Business、Enterpriseの違いを、実運用目線で判断できます。
  • n8n 料金を「実行回数」「同時実行数」「AI連携」「セルフホスト」の観点で見積もれるようになります。
  • OpenAI、LangChain、ベクトルDBを使ったAIワークフローの作り方と、コストを抑える設計がわかります。

結論（先に結論を述べる）

2026年時点のn8n Cloud 料金プラン 2026は、まずStarterまたはProで始め、実行回数・同時実行数・チーム管理が足りなくなったらBusinessまたはEnterpriseを検討するのが現実的です。公式価格では、Starterは年払いで20ユーロ/月、Proは50ユーロ/月、Businessは667ユーロ/月、Enterpriseは個別見積もりです。価格は変更される可能性があるため、導入前には必ず公式Pricingを確認してください。参考: https://n8n.io/pricing/

n8n Cloudの大きな特徴は、Zapierのような「ステップごとの課金」ではなく、基本的に「ワークフロー実行単位」で考えられる点です。1回のワークフロー内でHTTP Request、OpenAI、Google Sheets、Slack、条件分岐を何個つないでも、1回の実行として扱われるため、複雑なAI自動化ほどn8n Cloud 価格の読みやすさが効いてきます。

一方、n8n セルフホスト 無料はサーバー費用だけで使えますが、アップデート、バックアップ、HTTPS、認証、監視、障害対応は自分で持つ必要があります。初心者や小規模チームはn8n Cloud、DevOps体制がある組織はセルフホスト、監査・SSO・SLAが必要な企業はn8n Enterpriseが候補です。

n8n Cloud 料金プラン 2026の基本構造

n8n Cloud 料金プラン 2026を見るときは、月額だけでなく「月間ワークフロー実行数」「同時実行数」「共有プロジェクト数」「実行ログ保持」「AI Workflow Builderクレジット」を確認します。

プラン 目安価格 主な対象 実行数の目安 特徴
Starter 20ユーロ/月（年払い） 個人・検証 2.5K/月 1共有プロジェクト、5同時実行、50 AI Workflow Builder credits
Pro 50ユーロ/月（年払い） 小規模チーム・本番運用 10K/月 3共有プロジェクト、20同時実行、7日間のInsights、管理者ロール
Business 667ユーロ/月（年払い） 100名未満の企業 40K/月 SSO/SAML/LDAP、環境分離、Git連携、スケーリング
Enterprise 個別見積もり 大企業・高コンプライアンス カスタム SLA、外部シークレット、ログストリーミング、長期保持

公式Docsでは、n8n Cloudはインストール不要のホスト型、セルフホストは技術知識が必要な構成として整理されています。参考: https://docs.n8n.io/choose-n8n/

n8n 無料 有料 違いを一言でいうと、無料のセルフホストは自由度が高い代わりに運用責任が重く、有料のn8n Cloudはインフラ運用をn8n側に任せられる代わりに実行数や機能上限を意識する、という違いです。

どのプランを選ぶべきか

個人の学習、API検証、少数の業務通知ならStarterで十分です。たとえば、毎朝9時にGoogle Sheetsを読み込み、OpenAIで要約し、Slackへ投稿するワークフローを1日1回動かすだけなら月30回程度です。Starterの2.5K実行には余裕があります。

Proは、顧客対応、営業通知、レポート生成、Webhook連携など、本番ワークフローを複数持つ小規模チーム向けです。Webhookとは、外部サービスのイベントをきっかけにn8nを起動する仕組みです。フォーム送信、CRM更新、決済完了、GitHub issue作成などをリアルタイムに処理できます。

Businessは、SSO（シングルサインオン）、SAML/LDAP、開発・本番環境の分離、Gitバージョン管理が必要な会社向けです。ワークフローが個人の便利ツールから、部署横断の業務基盤になった段階で検討します。

n8n Enterpriseは、専用サポート、SLA、外部シークレット管理、ログストリーミング、長期監査ログが必要な組織向けです。金融、医療、大規模SaaS、社内の重要データ連携では、n8n Enterpriseのガバナンス機能が判断材料になります。

AI連携ワークフローの構築手順

ここでは、n8n Cloud 料金プラン 2026を前提に、問い合わせメールをAIで分類し、社内ナレッジを検索して回答案をSlackに出すワークフローを作ります。

手順1: Gmail Triggerを設定する

  1. 新規ワークフローを作成します。
  2. Gmail Triggerノードを追加します。
  3. EventはMessage Receivedを選びます。
  4. 検索条件にis:unreadやlabel:supportを指定します。
  5. 実行回数を抑えるため、全メールではなく対象ラベルだけをトリガーにします。

手順2: Setノードで入力を整理する

Setノードを追加し、AIに渡す項目を絞ります。たとえば、subject、from、body、receivedAtだけにします。不要な添付ファイルやHTML全文を渡すと、OpenAI APIのトークン費用が増えます。

手順3: AI AgentまたはOpenAIノードを接続する

OpenAIノード、またはAI Agentノードを追加します。分類タスクなら、プロンプトは次のようにします。

あなたはSaaSサポート担当です。問い合わせ本文を読み、category、priority、summary、suggested_replyをJSONで返してください。priorityはhigh、medium、lowのいずれかです。

LangChain系ノードを使う場合は、モデル、メモリ、ツールを分けて設計します。LangChainは、LLM、検索、外部ツール、会話履歴を組み合わせるためのフレームワークです。n8nではAI AgentにGoogle Sheets、HTTP Request、Vector Storeなどをツールとして接続できます。

手順4: ベクトルDBで社内ナレッジを検索する

FAQ、Notion、Google Docs、PDFマニュアルをベクトルDBに入れておくと、RAGを作れます。RAGとは、LLMが回答する前に外部知識を検索し、根拠を与える方式です。Pinecone、Qdrant、Supabase Vector、Postgres pgvectorなどを使えます。

基本構成は次の通りです。

  1. Schedule Triggerで毎日1回起動します。
  2. Google DriveまたはNotionノードで文書を取得します。
  3. Text Splitterで文章を小さなチャンクに分割します。
  4. Embeddings OpenAIでベクトル化します。
  5. Vector Storeへ保存します。
  6. 問い合わせ処理時にVector Store Retrieverで関連文書を検索します。

この構成なら、n8n Cloud 価格だけでなくOpenAIやベクトルDBの外部料金も見積もれます。大量の文書を毎回ベクトル化せず、更新分だけ処理するのがコスト削減の基本です。

料金を抑えるワークフロー設計

n8n 料金を抑えるには、無駄な実行を減らすことが最重要です。Cronで5分ごとに起動するワークフローは、月に約8,600回実行されます。Starterではすぐ上限に近づくため、Webhook化、差分取得、バッチ処理を検討します。

実践的には、次の設計が有効です。

  • ポーリングではなくWebhookを使う
  • IFノードでAI処理が必要なデータだけ通す
  • Mergeノードで複数データをまとめて処理する
  • Split In BatchesでAPI制限を守る
  • 成功時の実行データ保存を最小化する
  • エラー時だけ詳細ログを保存する

n8n Cloud 料金プラン 2026では実行ログ保持や保存実行数にも上限があります。長期分析が必要な場合は、ログをBigQuery、Datadog、Postgresなど外部へ送る設計を検討してください。

ワークフロー実装テクニック

トリガー設定

定期実行ならSchedule Trigger、リアルタイム連携ならWebhook、メール起点ならGmail Trigger、SaaSイベント起点なら各サービスのTriggerノードを使います。料金最適化の観点では、最初に「この処理は本当に定期実行が必要か」を確認します。

例: 問い合わせフォームなら、5分ごとの確認よりWebhookの方が実行回数を抑えられます。Webhook URLをフォームサービスに登録し、POSTされたJSONをn8nで受け取ります。

ノード接続

基本は、Trigger -> Set -> IF -> OpenAI -> Slackです。Setで入力を整え、IFで条件分岐し、必要な場合だけAIへ渡します。たとえばbody contains "請求"なら経理チャンネル、priority = highならサポート責任者へメンションします。

エラーハンドリング

本番運用ではError Triggerを使って、失敗時にSlack通知を出します。通知内容には、ワークフロー名、実行ID、失敗ノード、エラーメッセージ、再実行リンクを含めます。外部APIの一時障害に備え、HTTP Requestノードではリトライ設定とタイムアウトを明示します。

条件分岐の具体例

IFノードで次の条件を設定します。

  • priority equals highならSlackの#urgent-supportへ通知
  • category equals billingならNotionの請求FAQを検索
  • confidence lower than 0.7なら人間レビューへ回す
  • from contains example.comなら既存顧客としてCRMを検索

AI回答をそのまま顧客へ送らず、最初はSlackに回答案を出すHuman-in-the-loop構成にすると安全です。Human-in-the-loopとは、人間の確認を処理フローに入れる設計です。

よくある質問（FAQ）

Q1: n8n Cloudに無料プランはありますか？

A1: n8n Cloudには無料トライアルがありますが、継続利用の無料クラウドプランとして考えるより、検証期間と捉えるのが実務的です。無料で長く使いたい場合は、n8n セルフホスト 無料のCommunity Editionを検討します。ただし、サーバー運用やバックアップは自分で行います。

Q2: n8n Cloud 料金プラン 2026で初心者におすすめはどれですか？

A2: まずはStarterがおすすめです。月間2.5K実行の範囲で、Slack通知、Google Sheets更新、OpenAI要約、メール分類などを十分試せます。本番ワークフローが増え、同時実行や管理機能が必要になったらProへ上げます。

Q3: n8n Enterpriseはいつ検討すべきですか？

A3: SSO、SLA、監査ログ、外部シークレット、ログストリーミング、専用サポートが必要になった段階です。特に個人の自動化ではなく、全社の重要業務をn8nに載せる場合はn8n Enterpriseの検討価値があります。

Q4: n8n 料金はAI API料金も含みますか？

A4: 通常、OpenAI、Pinecone、Supabaseなど外部サービスの利用料は別です。n8n Cloud 価格はn8nの実行基盤や機能に対する料金であり、LLMのトークン費用やベクトルDBの保存費用は別途見積もる必要があります。

まとめ

n8n Cloud 料金プラン 2026は、実行回数ベースで複雑なワークフローを作りやすい料金体系です。Starterは検証・個人利用、Proは小規模チームの本番運用、BusinessはSSOやGit連携が必要な企業、n8n Enterpriseは厳格な統制が必要な大規模組織に向いています。

導入前には、1か月あたりの実行回数をざっくり計算してください。定期実行、Webhook、AIチャット、バッチ処理を分けて見積もると、n8n 料金の判断が明確になります。次のアクションは、StarterまたはProの無料トライアルで1つの実業務ワークフローを作り、実行ログとAI API費用を確認することです。公式情報はPricing、Docs、Blog、Communityで随時更新されます。参考: https://n8n.io/pricing/ / https://docs.n8n.io/ / https://blog.n8n.io/ / https://community.n8n.io/
